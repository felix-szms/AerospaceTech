🚨 P0 · 阻断性问题

P0-1 工具页面全部缺失 — 导航配置指向 10 个不存在的页面

config.ts 侧边栏和导航引用了以下路由，但仓库中 docs-site/tools/ 目录完全不存在：

/tools/mission-simulator、/tools/timeline、/tools/orbit-calculator、/tools/rocket-simulator、/tools/atmosphere、/tools/aerodynamics-lab、/tools/guide-nasa-eyes、/tools/guide-openrocket、/tools/guide-openmodelica、/tools/link-check

影响：用户点击导航栏任何"在线工具"链接都会 404。Vue 组件虽然写好了（OrbitCalculator.vue、RocketSimulator.vue 等），但没有对应的 Markdown 包装页面。

修复：为每个工具创建 docs-site/tools/xxx.md，在 Markdown 中引用对应的 Vue 组件。例如 <OrbitCalculator />。

P0-2 仓库缺少 package.json 和构建入口 — 无法 build

仓库根目录和 docs-site/ 目录都没有 package.json、package-lock.json、node_modules。CI/CD 配置 deploy.yml 中引用 package.json 和 npm ci，但文件不存在。

影响：GitHub Actions 部署流程无法执行；其他开发者 clone 后无法 npm install。

修复：提交 package.json（含 vitepress、vue、katex 依赖）和 lock 文件。建议同时提交 .gitignore 排除 node_modules。

P0-3 资源文件大量缺失 — Logo、图片、资源页均不存在

以下文件在代码中被引用但仓库中不存在：

  • docs-site/public/logo.svg — 被 config.ts 和首页引用
  • docs-site/resources.md — 被导航栏引用
  • docs-site/public/history/ 下应有 ~30 张历史图片，实际只有 7 张
  • docs-site/public/lesson-covers/ — 被 index.md 引用，完全不存在
  • docs-site/public/images/ — 被多个文件引用，不存在
  • docs-site/public/avatars/ — 被首页引用，不存在
  • docs-site/.vitepress/public/logo.svg — 另一处 Logo 引用路径

影响：首页和导航栏大量占位图无法加载，资源页 404。

P0-4 许可证声明矛盾 — README 说 MIT，LICENSE 文件是 GPL-2.0

README.md 明确写着 LICENSE: MIT，但 LICENSE 文件内容是 GNU GPL v2.0 全文。这是法律层面的矛盾。

修复：统一为一。如果是 GPL-2.0，修改 README；如果是 MIT，替换 LICENSE 文件。

P0-5 KaTeX 版本冲突 — package.json 引用 0.18.1，CDN 加载 0.16.11

index.md 通过 CDN 加载 KaTeX 0.16.11（CSS + JS），但 package.json 依赖 katex: ^0.18.1。如果 vitepress-plugin-katex 使用 npm 包渲染，而 head 中的 CSS 是旧版本，会出现公式渲染不一致或样式冲突。

修复：统一版本号。如果依赖 npm 包，不需要在 head 中重复加载 CDN。删除 head 中的 CDN 引用，让插件自行处理。

⚠️ P1 · 高优先级问题

P1-1 Vue 组件 Canvas 尺寸硬编码，不支持响应式

OrbitCalculator.vue 使用 width="600" height="600"，RocketSimulator.vue 使用 200×500（火箭）和 600×300（图表），AerodynamicsLab.vue 使用 300×500。在移动设备上这些固定尺寸会溢出或过小。

修复：使用 ref 获取容器 DOM，通过 ResizeObserver 或 clientWidth 动态设置 canvas 尺寸，保持宽高比。

P1-2 Canvas 动画持续运行，无可见性检测

多个组件（OrbitCalculator、RocketSimulator、AerodynamicsLab）使用 setInterval / requestAnimationFrame 持续渲染，即使用户已滚动到其他区域。这会消耗 CPU/GPU 和电池。

修复：使用 IntersectionObserver 检测 canvas 是否在视口内，不可见时暂停动画。同时在组件 onUnmounted 中清理定时器（部分组件已做，部分缺失）。

P1-3 ScienceDiagram.vue 内联巨大 SVG — 约 3000 行

ScienceDiagram.vue 将两个完整 SVG（空气组成饼图 + 大气层分层图）直接硬编码在模板中，合计约 3000 行。这导致：

  • 组件文件过大，难以维护
  • 所有 SVG 无论是否显示都被加载到 DOM
  • 无法复用图表组件

修复：将 SVG 拆分为独立文件（.svg 或独立 Vue 组件），通过 v-if 按需渲染。

P1-4 Vue 组件没有使用 TypeScript

虽然项目配置文件是 config.ts（TypeScript），但所有 14 个 Vue 组件的 <script setup> 都没有 lang="ts"。数据文件 historyData.ts 有类型定义但组件没有类型约束。

影响：缺乏类型检查，props 传递错误不会被编译器发现。对于教学项目，TypeScript 能提供更好的示范作用。

修复：为所有组件添加 lang="ts" 并定义 defineProps 的类型接口。

P1-5 组件间 CSS 大量重复

OrbitCalculator.vue 和 RocketSimulator.vue 中的 .formula-section、.formula-table 样式几乎完全相同（各约 100 行）。ResourceCard.vue 和 LessonTools.vue 也有大量重复的卡片样式。

修复：提取公共样式到 custom.css 或创建共享 CSS 模块（如 shared-formulas.css），各组件引用即可。

P1-6 GitHub Social 链接无效

config.ts 中 socialLinks 的 link 值为 https://github.com（GitHub 首页），不是实际仓库地址。导航栏 GitHub 图标点击后跳转到 GitHub 首页。

修复：改为实际仓库地址。如果项目在 Gitee，可以移除 socialLinks 或改为 Gitee 链接。

P1-7 所有 Vue 组件全局注册，首屏加载过重

theme/index.ts 全局注册了全部 14 个组件。即使某页只需要一个 OrbitCalculator，所有组件（包括巨大的 ScienceDiagram）都会被打包进首屏 JS。

修复：使用 VitePress 的 defineAsyncComponent 按需加载大型组件，或只在需要的页面局部注册。

P2-2 缺少无障碍支持（a11y）
  • Canvas 元素没有 aria-label 或 role 属性
  • 导航按钮（如 HistoryGallery 的前进/后退）缺少 aria-label（部分已添加）
  • Canvas 内容无法被屏幕阅读器读取，没有提供文本替代方案
  • 颜色对比度在暗色主题下部分区域可能不足（如 --c-text-muted）

修复：为所有交互元素添加 ARIA 属性；为 Canvas 提供 <noscript> 或文本描述作为降级方案。

P2-3 缺少 SEO 基础设施
  • 没有 sitemap 生成（VitePress 插件 vitepress-plugin-sitemap 可解决）
  • 没有 robots.txt
  • 没有配置 OG 图片（head 中缺少 og:image）
  • 缺少 @vueuse/head 或等效的 per-page meta 配置

修复：添加 sitemap 插件、robots.txt 和 OG 图片配置。

P2-4 没有 Light Mode 适配

config.ts 设置了 appearance: false，强制暗色主题。所有 CSS 变量只定义了暗色值。对于教学场景，部分教室环境可能需要亮色主题。

建议：启用 VitePress 默认的外观切换，或至少提供一个对比度更好的亮色方案。

P2-5 MathFormula.vue 使用 trust: true

KaTeX 配置中 trust: true 允许渲染任意 HTML（包括 <script>）。目前内容是硬编码的，没有安全风险。但如果未来扩展为动态内容或用户提交内容，将成为 XSS 漏洞。

修复：设置为 trust: false，或定义明确的 trust function 只允许安全的命令。

P2-6 historyData.ts 文件过大（3000+ 行）

所有历史数据（航空 + 航天 + 竞赛 + 里程碑 + 人物）全部在一个文件中。维护困难，且所有数据无论哪页使用都会被完整加载。

修复：拆分为多个数据文件（aviation.ts、space.ts、contests.ts、milestones.ts），按需导入。

大气参数计算器、轨道计算器、火箭仿真器、空气动力实验室等工具全部中文界面、本地运行、秒开。相比 NASA 英文工具在课堂上的"水土不服"，这些工具真正解决了教师痛点。工具设计遵循"先原理 → 再工具 → 后实践"的教学逻辑，不是简单的计算器包装。

🏁 总体评价

一句话总结

这是一个课程设计水平很高、但工程质量有明显短板的教学网站。内容层面（18 节课 + 竞赛体系 + 自研工具）已经可以打 88 分，但工程层面（缺失关键文件、导航大面积 404、文档不一致）阻碍了项目的可用性和可信度。

核心价值

这个项目最大的价值不在于技术实现，而在于对中学空天科技教育的系统化思考。18 节课的教学设计、PBL/EDP 方法论的落地、自研中文工具的课堂适配、五位一体的教学材料体系——这些都是经过深思熟虑的。技术上的问题都可以快速修复，但这种教学设计的深度是难以复制的。

最紧迫的 3 件事

  • ① 补全工具页面 — 6 个自研 Vue 组件已经写好了，只差 Markdown 包装页面。这是投入产出比最高的修复。
  • ② 提交 package.json — 没有它项目无法构建，所有 CI/CD 都是空转。
  • ③ 补全缺失的图片和资源 — Logo、课程封面、头像等缺失资源直接影响第一观感。

给开发者的建议
